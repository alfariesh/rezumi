title: "Job search and AI"
description: "Configure Cloudflare Browser Run for pages that need JavaScript, treg for job search and assistant web search, and an AI provider without blocking manual job saving."
---

Users can save pasted job descriptions, read public posting links and prepare resumes manually without adding
API accounts. This guide adds reading pages that need JavaScript, job search, assistant web search and AI assistance
to a working [Cloudflare Workers deployment](/self-hosting/cloudflare). Users set none of this up themselves.

| Service                | What it does                                                                          | Required for                                              |
| ---------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Built-in reader        | Reads public pages directly: JobPosting data first, then page text.                   | Active without credentials.                               |
| Cloudflare Browser Run | Reads a page again in a real browser when the direct reader finds nothing to read.    | Optional; pages drawn by JavaScript or behind bot checks. |
| treg                   | Job search on the **Jobs** page and web search for the assistant, paid by the server. | Optional job search and assistant web search.             |
| AI provider            | Extracts role, company, salary, requirements and other details from posting text.     | AI extraction and other AI features.                      |

Rezumi calls Browser Run, treg and the AI provider separately. Without Browser Run, only the direct reader runs.
Without treg, there is no job search and no assistant web search; the assistant asks for a link or pasted text
instead.

## 1. Read pages that need JavaScript with Browser Run

The direct reader goes first for every pasted job link, the assistant's page reading and Profile's personal website
reader. When it finds nothing to read (an empty page, a page drawn by JavaScript with only a few words or an "enable
JavaScript" note and no JSON-LD, a bot check, or a site that refuses plain requests), Rezumi reads the page again
through Cloudflare Browser Run's Quick Actions `/content` endpoint,
which opens it in a real browser and returns the rendered HTML. The address is always checked to be public `https://`
(no private or loopback addresses, DNS included) before anything is fetched or sent to Browser Run.

Create a Cloudflare API token with the **Browser Run Edit** permission, then set it and your account ID:

```jsonc wrangler.jsonc
// The 32-character Account ID from the Cloudflare dashboard. Not secret.
"vars": { "CLOUDFLARE_ACCOUNT_ID": "0123456789abcdef0123456789abcdef" }
```

```bash
pnpm exec wrangler secret put CLOUDFLARE_BROWSER_TOKEN
```

Both are needed; without them only the direct reader runs. Each person can have 20 pages read through the browser per
UTC day; past that, only the direct reader runs for them until the next day. Workers Paid includes 10 browser hours a
month, then $0.09 an hour. LinkedIn and Indeed often block automated reading even in a browser; point users to the
browser extension for those sites. For local development, add both values to `.env.local`.

## 2. Job search and assistant web search through treg

Job search on the **Jobs** page and the assistant's web search both run through [treg](https://treg.to) on your
account, with one token:

```bash
pnpm exec wrangler secret put TREG_API_KEY
```

Assistant web search asks Serper (Google results, about $0.001 a search) first, targeted by the person's search
countries, up to three countries searched in parallel. If Serper fails, treg's routed web search tries other search
providers within a $0.01 ceiling. The person approves each exact query before it is sent. The career coach searches
only when **Web research** is on for that message, and only a person's own AI connection runs web tools; Rezumi AI
does not.

Search spending counts toward the same daily server budget as job search, `JOB_SEARCH_DAILY_BUDGET_USD` (default 1 US
dollar). Once it is spent, search fails with "Web search reached today's limit on this server. Try again tomorrow."
Each person can also send 50 web searches per UTC day. See the
[environment reference](/self-hosting/environment-variables#job-search-and-web-reading).

## 3. Connect OpenAI or another AI provider

For OpenAI, follow its [API quickstart](https://developers.openai.com/api/docs/quickstart), create a key in the
[API dashboard](https://platform.openai.com/api-keys), and enable API billing. API usage is
[billed separately from ChatGPT subscriptions](https://help.openai.com/en/articles/9039756-managing-billing-settings-on-the-chatgpt-web-and-api-platform).

Set the provider and model in `vars` in `wrangler.jsonc`, and the key as a Wrangler secret:

```jsonc wrangler.jsonc
"vars": { "AI_PROVIDER": "openai", "AI_MODEL": "gpt-5-mini" }
```

```bash
pnpm exec wrangler secret put AI_API_KEY
```

`gpt-5-mini` is an example; choose a model your API account can use. Check its
[model documentation](https://developers.openai.com/api/docs/models/gpt-5-mini) for supported features. Reactive
Resume's Assistant needs a supported model with tool calling. Leave `AI_BASE_URL` unset
for OpenAI's default endpoint. The app reads `AI_API_KEY`, not `OPENAI_API_KEY`.

Other [supported providers](/guides/using-ai#supported-providers) use the same shared variables with their provider
identifier and model. An OpenAI-compatible gateway also needs `AI_BASE_URL`. For the other shared settings, see the
[AI environment reference](/self-hosting/environment-variables#ai-and-redis). A local model such as Ollama must be
reachable at a public HTTPS address from the Worker, because Cloudflare blocks private-network fetches; on a local
Node.js development server, local or private AI endpoints need `FLAG_ALLOW_UNSAFE_AI_BASE_URL=true`, which you should
enable only where you trust every user. Ollama can omit `AI_API_KEY`.

To see every shared AI request, its cost and errors in one place, put
[Cloudflare AI Gateway](https://developers.cloudflare.com/ai-gateway/) in front of the provider: create a gateway, then
set `AI_BASE_URL` to its provider endpoint, for example
`https://gateway.ai.cloudflare.com/v1/<account-id>/<gateway>/openai` for OpenAI. The provider key stays in
`AI_API_KEY`. New gateways require authentication: create a token in the gateway's **Settings** and store it as the
`AI_GATEWAY_TOKEN` secret. An OpenAI endpoint through the gateway keeps the Assistant's direct-OpenAI features. Leave
the gateway's **Collect Logs** off unless you need it: it stores prompts and replies, which hold people's resume data.

The AI key belongs to Rezumi for this workflow. treg receives search queries and Browser Run receives selected public
URLs; neither needs the AI-provider key or candidate resume data.

## 4. Apply settings and verify the workflow

On Cloudflare, set plain values in `vars` in `wrangler.jsonc` and secrets with `wrangler secret put`, then redeploy with
`pnpm deploy:cloudflare`. For local development, edit `.env.local` and restart `pnpm dev`. Keep keys in Wrangler secrets
or server configuration, never browser build variables.

1. Open **Applications**, select **Save a job**, paste a public posting link and review the role, company and retained
   description.
2. Try a posting link whose page is drawn by JavaScript. With Browser Run configured, the application's posting source
   shows it was read with `browser`.
3. Save the job as **Saved**, prepare a selected resume or a copy, and confirm **Mark as applied** after submission.
4. Try pasted text and a link that cannot be read. Failed reading should preserve the draft and offer pasted-text
   recovery.
5. With `TREG_API_KEY` set, ask the assistant (on your own AI connection) to look something up. Approve the query and
   check the **Sources** it lists.

`/api/health` checks database, storage and configured Redis; it does not verify these integrations. If a step fails:

| Symptom                               | Check                                                                                                                                  |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Pages drawn by JavaScript stay empty  | Set both `CLOUDFLARE_BROWSER_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`; check the token has **Browser Run Edit** and your browser hours left. |
| The assistant never offers web search | Set `TREG_API_KEY`; use your own AI connection, since Rezumi AI runs no web tools.                                                     |
| "Web search reached today's limit"    | The shared `JOB_SEARCH_DAILY_BUDGET_USD` is spent for today; raise it or wait for the next UTC day.                                    |
| AI extraction fails                   | Check provider billing, key and model access; verify all required [AI variables](/self-hosting/environment-variables#ai-and-redis).    |

## Career schedules

The same treg token powers [job alerts](/guides/finding-roles-automatically). Users enable a search schedule in **Career → Today**. Interview briefings use AI separately, and users must enable their preparation schedule too. Work runs on the server while the browser is closed.

On Cloudflare, the scheduler is the once-per-minute Cron Trigger in `wrangler.jsonc`; no runner secret is needed. Verify a due reminder in a dedicated test installation. See [Operating scheduled work](/contributing/career-platform#operate-scheduled-work) for setup, delivery and retry details.

Optional email copies require a verified user email, explicit user opt-in and working SMTP. In-app results stay available in Today. A successful health check does not establish that schedules or provider connections work.
