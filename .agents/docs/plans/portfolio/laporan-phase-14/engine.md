**`applyPortfolioEdits(data, edits, ctx)`**

- Every edit is first checked against `portfolioEditSchema`; then applied to a `structuredClone` of the current data; the result must pass `writablePortfolioDataSchema` and the 256 KB saved-size limit, else the edit is refused and the data stays as before it. Later edits still run. Unexpected exceptions are caught per edit too.
- One design keeps replay exact: strict mode only _resolves_ input (ids, refs, slugs, image objects, sanitized rich text, parsed links, metric shorthands); the structural step (insert/merge/remove/move plus cross-reference upkeep) is the same code in both modes; the resolved edit is read back from the parsed result (`add` → the stored item; `update` → the field diff, `null` for removed fields; `set` → the stored value, `null`/`"resume"` when absent). So replaying `applied.map(a => a.edit)` gives identical data, and `inverse` is computed from before/after data.
- Ops × lists: all 5 ops on works, services, testimonials, clients, custom, highlights, blocks (`workId`), metrics (`workId` + `blockId`). Positions `first`/`last`/`before`/`after`; list maxima checked with a clear message before the schema's.
- Refs: `ref` on the add, and on blocks and metrics created inside an add (`{type:"metrics", ref:"results", items:[{ref:"conv", …}]}`), usable wherever an id goes in later edits of the call, including `workId`/`blockId`, positions, `highlightMetricId`, and `custom:<ref>` section keys (in `sections.order/hidden/titles/hiddenItems` values and in keyed paths). A ref may not equal an existing id or another ref. A later edit naming the ref of a failed add is told so ("names the item edit #0 was to add, and that edit failed").
- Works: slug from `uniquePortfolioSlug`; an automatic slug follows a new title (editor's `retitleWork` rule); explicit `slug` checked (pattern, length, taken by another work → named); the old slug goes to the front of `previousSlugs` (max 5, `cleanSlugHistory` rule) only when the call started with it saved, like the editor's `changeWorkSlug` with `saved`. Update refuses `blocks`, `id`, `previousSlugs`, `fromResumeItemId`; add refuses `id`, `slug`. Strict refuses empty titles.
- Blocks: text (rich text), images (1–12, layout defaults like `newImagesBlock`), metrics (1–4), video (`parseVideoUrl`, YouTube gets `thumbnailUrl`), embed (`parseEmbedUrl`), link. PDF can't be added; it can be retitled/moved/removed. Type changes refused; a Metrics block's items change only through the `metrics` list. Changing a video/embed URL drops the old `thumbnail` copy unless a new one is given.
- Images: strict looks keys up among every image in the data (map pictures included) plus `ctx.images`, filling `width`/`height`/`thumbKey`; `alt` may be overridden; `caption` (images blocks) and `focus` (covers) allowed; unknown key → "Use a key from read_portfolio's images or uploads, or one save_attachment_image returned." Replay takes full objects.
- Rich text: plain text (no known tag) → `<p>` paragraphs with `<br>` for single breaks, HTML-escaped; then `sanitizePortfolioHtml` and `fitsRichText` ("at most 5000 characters of text (this has 5001)").
- `set`: all settable and keyed paths; `null` removes optional fields / resets defaulted ones; `basics.picture` null / `"resume"` / image ref; shorthands `design.accent` ("toska", "#rrggbb", "resume"), `design.fonts` (pair id, "theme", "resume"), `hero.effect` (effect id alone keeps target/phrases). Strict refuses font pairs, layouts and effects the current theme doesn't offer, naming what it offers. Empty basics/SEO/section-title text removes the override; WhatsApp numbers lose `+`, spaces and dashes.
- Metrics: `value` number → `{kind:"number"}`, string → `{kind:"text"}`; currency format needs `currency`, duration needs `unit` (refused, never guessed); other formats drop them (editor's `applyMetricFormat` rule).
- Cross-refs: removing a metric or Metrics block clears the work's `highlightMetricId` (inverse restores it); removing a Metrics block's last metric is refused; removing a custom section drops `custom:<id>` from order/hidden/titles/hiddenItems (inverse restores all); adding a custom section inserts its key before `contact` when `sections.order` is non-empty.
- Testimonials: add needs `consent: true` and a quote; `consent` other than `true` refused with a message telling the model to ask first.
- Plan (strict, `ctx.plan` non-null): `portfolioFeaturesNeeded(callStartData, after)` after every edit (same comparison as the server's save check, so keeping/leaving/returning to a stored premium theme within a call is allowed) and works over `maxWorks`. Messages name the plan and say "Don't apply it: tell the user it needs Plus and suggest it instead."
- Errors read like `works › "Work without pictures" › summary: at most 240 characters`; issues already present before the edit are marked "(already wrong before this edit: fix it first)".
- Summaries: `Added work "Lumen"`, `Updated metric "Revenue" in work "Coffee ordering app": format, currency`, `Moved client "Lumen" before client "Kilau Pay"`, `Set design.accent to {…}`, `Removed basics.headline: the page follows the resume again`.

**`portfolioAiView(input)`**: page (published, url, language, whether it follows the source); source; plan (name, maxWorks, locked features) or null; theme + catalog (id, name, free/plus, one-line `character`, `locked` for Plus themes not already in use); design (stored scheme/accent/fonts/variants, theme's scheme, and `offered`: the theme's variants, font pairs with labels, effects, `lockedEffects`, accent colours); basics (`{value, override}`, source location only while shown, picture source); hero (incl. highlights with ids, effect, background image ref); about; works with blocks (rich text in full; video/embed as page URLs; no previousSlugs, thumbKeys or dimensions); services, testimonials, clients, custom; sections in effective order (title in the page's language or custom, hidden, `onPage` from `buildPortfolioView`, `from`, CV items with ids, labels, when, `hidden` on the portfolio, `hiddenInSource`); location without coordinates; contact switches with `sourceHas` / `numberSet` only; seo; credit; images with `usedIn`; uploads; limits (works used/max with the plan, list maxima).

**`PORTFOLIO_EDIT_GUIDE`**: ~10.3K characters (~2.6K tokens). Ops, lists and item fields, value shapes, every settable path, rules, 7 worked examples (add a work with blocks + cover from an upload + move by ref; rewrite About; theme + accent + fonts; hide a CV item + rename a section; reorder/hide sections; add a metrics block then highlight it via a nested ref; remove a work). Every enum (themes with Plus marks, accents, font pairs, effects with Plus marks, button kinds, block types, layouts, metric formats/currencies/units/directions, variants, job types, work modes, backgrounds, section keys, rich-text tags) and every limit is generated from the schema constants. A test applies each example to the fixture in strict mode.

- **Web (replay):** pass plain data to `applyPortfolioEdits` (the store's current state, not an immer draft: the engine `structuredClone`s it); use the replay result's own `inverse` for Undo (computed on the editor's data, which may differ from the server's copy); replay never checks the plan or image keys. Resolved `set` edits use `null` for "removed" and `"resume"` for `basics.picture` following the CV.
- **Web (labels):** `portfolioEditItemName(dataBefore, edit)` gives the work/section title, client/testimonial name or metric label an edit touches (null for `set`). For `add`, `edit.item` holds the full item. Resolved `update.fields` lists exactly the changed fields (derived ones like `slug`/`previousSlugs`, `thumbnailUrl`, `currency: null` included).
- **Server/MCP:** `PortfolioEditPlan` = `{ maxWorks: entitlements.limits.portfolioWorks, features: { premiumPortfolioThemes, premiumHeroEffects, hidePortfolioCredit }, name }`, `null`/`undefined` when billing doesn't apply. Plan comparison uses the data passed in as the baseline, so pass the stored data (or the run's working copy) as `data`. `ctx.images` may include placed uploads; it's only a lookup.
- **Exports available:** `applyPortfolioEdits`, `portfolioFeaturesNeeded`, `portfolioAiView`, `PORTFOLIO_EDIT_GUIDE`, `PORTFOLIO_THEME_CHARACTER`, `placedPortfolioImages`, `portfolioEditItemName`, types `PortfolioPlanParts`, `PlacedPortfolioImage` and the Langkah 0 types.
- **Prompt wording:** the guide tells the model to read first, never send ids, use refs, set the theme before fonts/layouts, and suggest Plus rather than apply locked things; the system prompt doesn't need to repeat the field reference.

## Not done

- Keyed path values for `sections.hiddenItems.<key>` aren't checked against the source's real item ids (the engine has no resume in its context); unknown ids are harmless.
- When a work takes a slug that another work holds in `previousSlugs`, the other work's history isn't pruned (one resolved edit can't express a change to two works; the page resolves current slugs first, so links still work). The editor prunes it.
- No dedicated test for the 256 KB saved-size refusal (the check runs after every edit; a fixture that size would slow the suite).
